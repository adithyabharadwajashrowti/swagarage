# Swagarage

B2B corporate-gifting marketplace: catalogue, quote requests, Gift Assistant with PPT decks, and a staff admin.

**Stack:** React 19 + TypeScript + Vite · Supabase (Postgres, Auth, Storage, Edge Functions) · Vercel.

```
src/                 web app
  lib/               data access, auth, cart, assistant, PPT deck, CSV import, validation
  pages/             storefront, auth, account
  admin/             staff + admin area
supabase/
  migrations/        schema, row-level security, functions, storage, reference data
  seed.sql           135 products (generated by scripts/build-seed.py)
  seed-images/       product images for the seed
  functions/         notify-quote (email on new quote)
  tests/             database security tests
scripts/             test-db.sh, upload-seed-images.mjs, build-seed.py
```

## What it does

| Area | Features |
|---|---|
| Storefront | Home, categories, occasion collections, search and filters, product pages, MOQ enforcement |
| Quote | Cart saved in the browser, colour + branding notes per line, quote request with contact details |
| Gift Assistant | "Diwali gifts under ₹1500 for 200 people" → shortlist → **downloadable PPT in the Swagarage template** |
| Accounts | Sign up with email confirmation, sign in, password reset, profile, quote history and status timeline, cancel |
| Admin (staff) | Dashboard, quote pipeline with client messages + internal notes, product editor with image upload, bulk publish, proofreading-sheet CSV import, vendors and costs, category margins with automatic pricing (capped at MRP) |
| Admin (admin) | User roles, audit log of every change |
| Duplicates | Same product from two vendors → **Merge a duplicate** on the product page: one listing for clients, all vendor offers kept internally, cheapest cost and lower MRP win |
| Logo rule | Per product: keep brand logo / replace vendor logo with Swagarage / remove (also a `Logo` column in the sheet) |

## Built for traffic

- **Catalogue from the CDN.** Each catalogue version is published as one immutable JSON file in Supabase Storage (served by its CDN). A visit costs the database one tiny version check; returning visitors reuse their browser copy. If a version isn't on the CDN yet, the database serves a prebuilt snapshot (never a per-visitor join). Admin pages publish new versions automatically every 30 s while staff work.
- **Small public bundle.** Admin and account code load only when needed; the PPT library loads only when someone downloads a deck.
- **Measured** on a 2-CPU machine with 5,000 products and 50 concurrent connections (`npm run test:load`):

| Request | Throughput | Avg latency |
|---|---|---|
| Repeat visit (version check) | ~18,000/s | 3 ms |
| Product page | ~11,000/s | 4 ms |
| First visit, full catalogue snapshot from DB (CDN normally serves this) | ~330/s | 150 ms |
| Account page | ~1,300/s | 38 ms |
| Quote submission | ~1,100/s | 46 ms |
| Mixed realistic traffic | ~680/s | 73 ms |

  Old approach (catalogue queried with joins per visitor) managed ~13 full catalogue loads/s, so first visits are now ~25x cheaper before the CDN even comes in. On Supabase, start on the Small compute add-on or above for launch traffic and enable the connection pooler.

## 1. Run it locally

Needs Node 20+.

```bash
npm install
cp .env.example .env.local      # then fill in the two values (step 2)
npm run dev                     # http://localhost:5173
npm test                        # unit tests (assistant parser, CSV import)
npm run test:db                 # database security, attack, privilege and race tests (needs PostgreSQL 15+)
npm run test:load               # load test: 5,000 products, 3,000 clients, 50 concurrent connections
```

## 2. Set up Supabase (hosted)

1. Create a project at supabase.com (region: Mumbai `ap-south-1`).
2. Apply the database: `npx supabase login`, `npx supabase link --project-ref <ref>`, `npx supabase db push`.
   (Or paste each file in `supabase/migrations/` into the SQL editor, in order.)
3. Load products: run `supabase/seed.sql` in the SQL editor, then upload images:
   ```bash
   SUPABASE_URL=https://<ref>.supabase.co SUPABASE_SERVICE_ROLE_KEY=<service key> npm run seed:images
   ```
   The service role key stays on your machine. Never put it in `.env.local` or any `VITE_` variable.
4. **Authentication settings** (Dashboard → Authentication):
   - Providers → Email: *Confirm email* ON, *Secure email change* ON, minimum password length **10**, require lowercase, uppercase and digits.
   - URL configuration: Site URL = your domain; redirect URLs = `https://<domain>/login`, `https://<domain>/reset-password`.
   - Rate limits: keep the defaults or tighter.
   - SMTP: add your own SMTP (e.g. Resend) before launch; Supabase's built-in sender is for testing only.
5. Copy **Project URL** and **anon public key** (Settings → API) into `.env.local`.
   Optional bot protection: create a Cloudflare Turnstile site, put the site key in `VITE_TURNSTILE_SITE_KEY` and the secret in Supabase → Authentication → Bot and Abuse Protection.
6. Make yourself admin: sign up on the site, confirm the email, then in the SQL editor:
   ```sql
   update public.profiles set role = 'admin' where email = 'you@example.com';
   ```
   After that, manage roles from **Admin → Users**.
7. Publish products: proofread them, then **Admin → Products → select → Publish** (or import the sheet with "Publish rows marked OK or Fixed").
8. Full catalogue (kept out of this repo on purpose): run the private `import_catalogue.sql` in the SQL editor, then upload its photos:
   ```bash
   SUPABASE_URL=https://<ref>.supabase.co SUPABASE_SERVICE_ROLE_KEY=<service key> node scripts/upload-images.mjs <private folder>/images/catalogue catalogue
   ```
   Supplier names and costs go only into tables that no app user (admins included) can read. Selling prices are computed in the database from the cheapest cost.

## 3. Quote email notifications (optional)

```bash
npx supabase functions deploy notify-quote --no-verify-jwt
npx supabase secrets set WEBHOOK_SECRET=<32+ random chars> RESEND_API_KEY=<key> \
  NOTIFY_EMAIL_TO=orders@yourdomain NOTIFY_EMAIL_FROM="Swagarage <quotes@yourdomain>" SITE_URL=https://yourdomain
```
Then Dashboard → Database → Webhooks → new webhook on `public.quotes`, event INSERT, type *Supabase Edge Function* `notify-quote`, add header `x-webhook-secret: <same secret>`.

## 4a. Deploy on GitHub Pages

1. Push to a **public** GitHub repo (branch `main`).
2. Repo **Settings → Pages → Source: GitHub Actions**.
3. Repo **Settings → Secrets and variables → Actions → Variables**: add `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY` (the **publishable** key, never the secret one), and `VITE_WHATSAPP_NUMBER` (the business WhatsApp number that receives "Enquire on WhatsApp" messages, e.g. `919876543210`).
4. **Actions** tab → *Deploy to GitHub Pages* → *Run workflow* (later pushes deploy automatically). Site: `https://<user>.github.io/<repo>/`.
5. Supabase → Authentication → URL Configuration: Site URL = that address; redirect URLs = `<address>login` and `<address>reset-password`.

Pages can't send HTTP security headers, so the Content-Security-Policy ships as a `<meta>` tag; clickjacking protection (`frame-ancestors`) needs a host with headers, such as Vercel.

## 4b. Deploy (Vercel)

Import the GitHub repo in Vercel, add `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY` as environment variables, deploy. `vercel.json` adds SPA routing and security headers (CSP, HSTS, frame blocking).

## Day-to-day

- **New products:** add them to the proofreading sheet (one row per product, unique ID), save as CSV, **Admin → Import sheet**.
- **Prices and costs:** costs and suppliers are never handled in the app or the admin. They live only in the database's private tables, loaded through the Supabase SQL editor with a private import file. Selling prices follow automatically from the cheapest cost, using pricing slabs that are also kept private (rounded to ₹1). GST, branding and shipping are added at checkout.
- **Quotes:** **Admin → Quotes** → open → set status, quoted total, message to client (client sees it), internal notes (client never sees them).

## Proofreading sheet columns

`ID, Status, Name, Brand, Category, Subcategory, Price (INR), Price basis, MOQ, Colours, Dimensions, Material, Weight, Laptop fit, Model, Warranty, Other specs, Features, Branding possible, Ready stock (units), Under production, Collections` and optionally `Logo` (keep / replace / none). Any cost or supplier columns are ignored.

Status: `OK` / `Fixed` (can be published), `Remove` (archived), blank (stays in review). Lists: colours and collections comma-separated, features separated by `|`, other specs as `Name: value; Name: value`.
